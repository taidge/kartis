# D3 等值线与密度估计：下一阶段准备

历史计划：下文保留准备阶段的范围、问题和原始证据。2026-11-12 已正式迁入根库核心与原版参考检查，浏览器、示例和统一回归验收仍在进行；当前状态以 [验收记录](verification.md) 和 [差距清单](feature-gaps.md) 为准。

参考固定为 d3-contour 4.0.2 的 `src/contours.js`、`density.js`，以及本地
D3 官方文档 `docs/d3-contour/{contour,density}.md`。运行时继续使用 Rust，
JavaScript 原包只作为独立参考，不进入默认图表依赖。

## 数据与算法边界

- 网格是显式宽高和按行排列的有限 nullable 标量。每个单元样本对应
  `(i + 0.5, j + 0.5)`；输出是平面多边形集合，不能误当经纬度交给球面投影。
- 每个阈值表示数值大于等于它的区域。实现完整 16 种 marching-squares
  情形，包括 5/10 歧义格的 D3 固定连接方式、边界虚格、闭环拼接、孔洞归属、
  可选线性平滑和缺失单元。已有路径 morph 不是这些计算的替代品。
- 原始计算与 Scene 布局分开。候选接口为借用网格、显式/计数阈值配置、
  单层及多层等值结果；结果保留阈值、外环和孔洞，不合成业务原始观测值。
- 显式阈值排序和重复值需要保留来源。Scene 身份由阈值和重复出现序号组成，
  不积累旧阈值历史。自动阈值的空值、常值和端点规则须执行原包冻结参考后确定。
- 每层保留完整有向环和非零绕组填充。不能为了语义路径单节点预算而将孔洞
  拆成独立实心 mark；大路径沿用直接 SVG/Canvas 或显式 raster 的既有边界。

## 密度估计

- 显式点坐标、权重、二维尺寸、带宽、单元尺寸和阈值；不引入资源加载或网络。
  原始估计器使用像素坐标，数据尺度投影与域导航应在布局层明确绑定。
- 对照实际 D3 的加权网格沉积、单精度存储、重复盒式模糊、边缘扩充、单元
  尺寸向下取二次幂，以及输出阈值的每平方像素单位。不能用一个名称相似的
  高斯函数替代 D3 的整条计算链。
- 单精度累积必须逐次与原包比较，不能先累计 f64 再最后转换。带宽为零、
  重复点、离图点、零权重和符号权重均需单独核对，再明确有限支持范围。
- 可准备显式拥有的不可变密度网格，重复求阈值时复用网格而不重扫业务源。
  网格不保留点历史、宿主对象或全局缓存。

## 有界计算与绘制

网格乘积、层数、工作量、边数、累计输出点/环/路径命令均须在扩大分配前
检查，并使用受检整数运算。阈值数不能乘出不受控全网格扫描。闭环拼接使用
当前边图和显式工作预算，避免不断复制并合大环导致二次方开销；遍历顺序须
确定，不能由 HashMap 枚举顺序决定产物。孔洞匹配也计入累计预算。

Scene 层复用现有图层、裁剪、颜色尺度、真实墨迹拾取和资源退休。提示值表示
当前层阈值，不伪装成某个单元值。孔洞和不相连区域不能被外包框或虚构中心
填满；动画、交互和宿主发布须保留现有原子拒绝与旧帧行为。

## 独立验收

1. 固定原包版本并冻结参考：1×1、单行/列、全部 16 格态、平台/斜坡、零/负值、
   相等阈值、nullable、分离岛、单/多孔洞、嵌套岛、smooth 开关和重复阈值。
2. 对比平面坐标、环方向、孔洞归属和面积。只允许明确的循环起点/分量排序
   规范化，不以大容差、抖动或丢洞来掩盖拓扑差异。
3. 密度另对照实际 Float32 网格、最大密度、阈值单位及路径。覆盖不同带宽、
   网格大小、权重、顺序和边缘情况，保留最初失败证据。
4. 检查坏尺寸/数据/阈值和各项预算拒绝；直接调用和受控更新均保留旧结果。
5. SVG、Canvas、CPU 检查独立位置与孔洞像素、绘制顺序、真实拾取、更新、
   清理；再接入保留式浏览器和原生消费者。不能用纯算法或编译通过代替。

等值线与密度完成后仍需继续推进可编辑 Brush、更多图型配置、地理支持范围
和平台能力；这份准备文档不改变整个 Nivo/D3 对齐目标。

## 冻结期间的实际参考准备

仅在 metadata 返回的 `target_directory` 下建立独立
`d3-contour-reference`，未修改冻结源码、WASM 包或正式画廊。执行原版
`d3-contour 4.0.2`，并显式固定其参考依赖 `d3-array 3.2.4`；临时脚本
`prepare-reference.mjs` 生成 `prepared-reference.json`，记录源文件 SHA-256。
当前有 540 组网格配置、500 组密度配置，覆盖上述拓扑、自动/显式阈值、
平滑、不同带宽/网格、符号权重和原始 Float32 网格。这是下一阶段参考草案，
正式小型 fixtures 与 Rust 差分测试尚未建立。

临时 `prepare-compact-fixture.mjs` 另生成 540 组网格 CSV（245,108 字节）和
从十种点集、五种带宽、五种请求 cellSize 中选取的 100 组密度 CSV
（2,303,897 字节）。选取是明确的交错组合，不是完整参数笛卡尔积；原始
500 组密度参考仍保留。几何编码逐层保留阈值、分离多边形和孔洞，并与原版
JSON 做无损往返核对。独立临时 Rust 读取器无需 serde，已校验 640 组记录、
3,308 个多边形、3,544 个闭环、51,116 个有限坐标点，以及 168,852 个有限
Float32 单元的十六进制位模式；尚未与 Rust 轮廓/密度实现做差分比较。

原包实际结果确认：常量和全缺失网格在自动阈值模式下输出空层集，但显式
阈值仍可生成有效满格轮廓；空密度的自动阈值也输出空层集。`[32,24]` 范围、
cellSize=4、点 `[16,12,1]`、bandwidth=0 的实际沉积包含最小值 `-0.75`，
最大每平方像素密度为 `0.140625`。bandwidth=2 仍有负单元值，不能因输入
权重非负而把底层网格钳成零。负权重场也不等于全负网格。

尚须决定明确的 nullable/NaN 输入契约、阈值排序与重复身份，以及异常参数
的受检支持范围；原包允许的隐式转换、非有限值和无界分配不直接成为公共 API。

原包还存在需要显式记录的缺失值差异：2×2 网格 `[1,1,null,1]` 在阈值 0
或 -1 输出空几何，而仅将该 `null` 换成 NaN 会保留其他三个采样的区域。
该差异来自末行首项直接比较，与其余单元的 nullable 判断不同。Rust 的
`Option<f64>` 不应根据单元位置改变缺失含义；候选规范是 `None` 一律按
NaN 的“低于阈值”分支处理。正式 oracle 应同时保留原包差异记录与该受检
profile 的参考输入，不能静默丢掉用例后声称 nullable 完全一致。

另有六组 15×15 的四层嵌套区域参考
`nested-hole-ownership.json`：同时包含外区/大孔/内岛/岛中孔。实际 D3
先完成内岛多边形，再完成最外多边形；每个外环分别拥有一个孔。因此若新的
边图遍历以最外环开始，不能简单把孔分给第一个包含它的外环；必须保留正确
的包含层级或选择最内层有效外环。环的循环起点和多边形顺序可以规范化，
孔洞归属不能随遍历顺序改变。

## 独立 Rust 草稿进展

协调冻结期间获准在 `target/contour-prototype` 的独立 workspace 推进算法。
metadata 返回其正常产物目录 `target/contour-prototype/target`；没有变更主项目
源码、包或画廊。草稿仅使用 std，并附有 D3 ISC 通知。

- 已实现 marching-squares 的完整 16 格态、确定的链式片段拼接、D3 完成顺序、
  平滑、孔洞归属、Sturges/计数/显式阈值。片段拼接只改链，不反复复制合并大环；
  缺失值统一采用前述 NaN profile。
- 已实现有权重和符号权重的 Float32 网格沉积、重复分数盒式模糊、有效 cellSize、
  padding、最大密度、单层与多层轮廓。只保留当前聚合场；不保留业务点。轮廓
  直接借用 Float32 场，不另建整份 nullable f64 网格。
- 固定全局最大 profile 与可下调预算，覆盖源样本、网格、层数、扫描/孔洞工作、
  边、点、环以及数值溢出；源数据始终借用且不修改。
- 五项独立 Rust 测试已通过：546 组网格轮廓（含六组四层嵌套）、500 组密度、
  844,260 个逐位相同的 Float32 单元、阈值单位/最大值/原包路径、非法参数和
  累计预算，以及下面的负最大值反例。Rust 1.95 与严格 Clippy 均通过。

首轮等值线对照曾在 `noise-5` 的平滑退化环上失败；原失败、详细几何和修正后
日志分别保留于独立 workspace 的 `target`。不能删掉退化环来通过对照。

另一个实际原包反例保存在 `signed-negative-maximum.json`：4×4、零带宽、
cellSize=1、每格中心权重 -1 时，最大密度为 -1。D3 批量 Count 输出的首层
标为 0 却携带 -1 的满格区域；其独立 `field(0)` 则为空，`field(-1)` 为满格。
草稿保留计数阈值顺序，但每层几何与它自己的阈值绑定，并对照实际单层接口；
显式阈值先稳定排序再计算，重复层保留。该差异须随正式 API 明示，不能声称
复制了原包全部隐式排序/重标行为。

尚待正式接入公共 API、Scene/颜色/metadata/真实拾取、浏览器与 CPU/Glory
消费者，以及更新/拒绝/清理的完整验收。纯算法证据不能代替这些交付。

隔离的 `draft/layout.rs` 已进一步借用主项目冻结的编译产物验证 Scene 适配草稿，
没有加入主项目依赖图或修改运行时。它保留每层完整外环/孔洞、真实阈值、当前
阈值/重复序号身份、按阈值声明配色和显式图例；路径锚点选取实际命令端点，
不从孔洞包围框造点。两项草稿验收已通过：四层嵌套的实际 CPU 像素、Scene
与类型化 Surface 的 Exact 命中、Glory 内存宿主挂载/清理，以及阈值插入、
隐藏/空层和非法帧原子拒绝。

实际 Chrome 对同一草稿的 SVG/Canvas/CPU 图像也已验证两层孔洞和两层实心
区域。SVG/Canvas 平均通道差为 0，SVG/CPU 为 0.020847750865051903，维持
小于 0.5 的阈值；十五个独立实心/空白像素检查全部通过。产物位于独立
workspace 的 `target/scene-draft`。这仍是隔离适配草稿；正式公共入口、密度
布局、保留式浏览器更新/输入、较大路径的明确目标边界和全项目检查尚未交付。
