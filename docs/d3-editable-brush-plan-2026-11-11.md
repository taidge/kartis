# 可编辑 Brush：交付范围与原验收要求

状态：共享状态机、Surface、浏览器 SVG/Canvas 与原生 Apace headless 接线已完成本阶段统一验收。
四引擎独立专项、完整 165 套矩阵、Chrome 五组及原版 D3 参考复验通过。
原生 raw modifiers 需应用显式转发，真实设备和辅助技术仍属后续平台验收。
实现入口见 [使用说明](editable-brush.zh-CN.md)，成绩及首轮失败处理见 [验收记录](verification.md)。
以下保留原需求和验收设计，不据此扩大已交付范围。

参考为 [d3-brush 3.0.0 源码](https://github.com/d3/d3-brush/blob/v3.0.0/src/brush.js)
及本地官方文档 `E:/Repos/d3/docs/d3-brush.md`。目标是共享 Rust 状态机和
实际宿主接线，不移植 D3 的 DOM selection、全局事件注册或 JavaScript 回调接口。

## 已有能力与新增边界

`SurfaceModel` 已有从起点拖出矩形、画面约束、命中 ID、连续/完成通知与取消。
浏览器目前由 Shift 启动该手势。`DomainViewport` 已能将画面 Brush 请求转换为
指定轴的数据窗口。这些继续保留；新增工作是当前选区的编辑与持续生命周期。

- 提供 X、Y、XY 三种模式；单轴模式的另一维覆盖明确的 plot extent。
- 提供移动选区、边/角调整、反向越边后继续拖动、受限平移，以及程序设置/清空。
- 分开表示无选区、正在创建的零宽临时选区、终止后有效选区。单轴终止只检查
  活跃轴，不能因另一维退化而误清除。目标选区、控件命中和画面反馈共用坐标。
- 可选修饰键策略覆盖居中调整、临时平移、主方向锁定及强制创建；与现有
  Shift 启动、键盘数据导航、平移和双指缩放明确仲裁。
- 通知区分开始、变化和结束，并标识操作模式与用户/程序来源。回调提交新布局、
  清空或替换选区时不再使用过期手势基准；相同状态不产生无限通知循环。

## 接线与资源生命周期

候选实现是独立受检控制器，再显式接入 Surface 与浏览器，不让工具栏、CPU
图像宿主或原有调用者必须伪造 DOM 事件。选区本身属于宿主逻辑像素；Scene
Transform 和数据域 Relayout 的换算只在边界完成一次。resize、plot 变化和
模式切换采用明确的保留/约束/清空策略，不静默把旧像素当成新域值。

保持当前输入的事务准入：非法 extent、不可表示坐标、布局/绑定或画面发布失败
时保留已接受帧和选区。活动指针、失去 capture、隐藏、stop、drop、数据退休与
焦点离开须终止对应手势，不能留下键盘监听或遮罩。异步/排队输入带当前会话
身份，取消后的旧 move/up 不得重建选区。只保留当前选区、手势起点及有限指针。

浏览器需实际画出可命中的边/角，SVG 与 Canvas 共用控制器；Canvas 不能仅在
静态 SVG 导出里出现手柄。DOM/CSS 正向容器缩放、DPR 和 viewBox 都应使用
逻辑坐标。控件对焦、键盘调整和可访问名称须单独定义与验收。

## 独立验收

1. 用真实 d3-brush 3.0.0 在浏览器执行固定输入轨迹，冻结每步选区、模式、
   通知顺序和手柄几何；不以自身状态机反生成预期值。
2. 覆盖全部八方向手柄、X/Y 两方向、四边约束、越边翻转、居中、锁轴、Space
   按下/释放、修改选区时的连续基准，以及清空和零跨度终止。
3. 程序设置/清空、重复值、回调更新、非法输入、resize、Transform/Relayout、
   当前数据、反向尺度、隐藏与会话退休都保留独立回归。
4. 四家浏览器的实际指针/capture、触摸与键盘轨迹；检查选区、手柄墨迹、命中、
   数据 ID 和清理。复用既有阈值，保留首次失败证据。
5. 共享控制器通过不等于原生设备通过；CPU 图像/Glory 宿主的实际接线与物理
   输入、辅助技术验收分别记录。D3 的 transition 对象与任意 DOM 改写不是
   Rust API 的兼容承诺，需动画时显式接入现有帧协议。

该工作与等值线/密度独立推进；本轮实现和验收不缩减其他 Nivo 配置和平台差距。
