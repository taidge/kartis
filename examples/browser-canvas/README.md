# Rust/WASM Canvas example

This independent Cargo workspace demonstrates `kartis::render::draw_canvas` on
an application-owned `HtmlCanvasElement`. Rust handles layouts, DPR-aware paint,
pointer hit testing, selection, keyboard traversal, legend filtering and window
resize. Listeners are owned and removed by the exported `stop()` function.

Prerequisites: the `wasm32-unknown-unknown` Rust target, wasm-bindgen CLI
**0.2.130**, PowerShell, and any local static HTTP server.

```powershell
./build.ps1
python -m http.server 8080 --bind 127.0.0.1
```

Open <http://127.0.0.1:8080/>. `build.ps1 -Debug` uses the debug profile. The
build script discovers the actual artifact directory through `cargo metadata`
and inherits Cargo configuration and environment unchanged.

The HTML contains an accessible data table and status region. Canvas keyboard
navigation is a small demo interaction contract; actual assistive technology
acceptance remains application-specific. This does not mount a semantic Canvas
node in Glory: Glory's existing `Graphic` Widget adapter remains the SVG path.

`pkg/` is generated by wasm-bindgen and intentionally excluded from version
control. The page contains no JavaScript chart calculation or drawing logic.
